# 5. Правила Handler


Handler отвечает только за Telegram.


Разрешено:


- получать сообщения;
- получать callback;
- запускать FSM;
- вызывать Service;
- отправлять ответы.


Запрещено:


- писать SQL;
- обращаться к Session;
- менять данные напрямую;
- считать бизнес-логику.


Пример плохого кода:


```python
await session.execute(
    select(Object)
)

Так делать нельзя.

Правильно:

await object_service.get_objects()
6. Правила Service

Service содержит бизнес-логику.

Здесь находятся:

расчеты дат;
проверка правил;
создание объектов;
создание счетов;
изменение расписаний.

Пример:

Перенос даты проверки:

Service:

получить дату

проверить выходной

перенести дату

сохранить результат
7. Правила Repository

Repository работает только с базой.

Он отвечает за:

SELECT;
INSERT;
UPDATE;
DELETE.

Repository не знает:

Telegram;
FSM;
кнопки;
сообщения.
8. Работа с базой данных

Использовать:

SQLAlchemy 2.x

Только async.

Пример:

Использовать:

async def get_object()

Не использовать:

def get_object()

Шаг 3

Создать или изменить Model.

Шаг 4

Шаг 5

Создать Service.

Шаг 6

Создать FSM.

Шаг 7

10. Правила моделей SQLAlchemy

Каждая модель должна:

иметь понятное имя;
иметь created_at;
иметь updated_at если требуется;
использовать связи SQLAlchemy;
иметь правильные типы.

Не создавать:

огромные универсальные таблицы.

11. Работа с датами

Все даты хранить правильно.

Использовать:

datetime

date

Не использовать:

строки:

"20 августа"

Для пользовательского ввода использовать отдельный parser.

12. Работа с ролями

В проекте есть:

admin

engineer

accountant

Не создавать отдельные таблицы:

admins

engineers

accountants

Если пользователь отличается только ролью.

13. Telegram FSM

Каждый сложный сценарий должен использовать FSM.

Например:

Создание объекта:

ObjectCreate.name

ObjectCreate.address

ObjectCreate.engineer

ObjectCreate.date

Не хранить временные данные в базе.

14. Кодовый стиль

Использовать:

Type hints.

Пример:

async def create_object(
    name: str,
    address: str
) -> Object:

Использовать:

понятные названия.

Плохо:

obj1
data2
x

Хорошо:

object_repository
inspection_date
15. Структура файлов

Не создавать:

main.py 3000 строк

Каждый файл должен иметь одну ответственность.

16. Обработка ошибок

Ошибки должны:

логироваться;
корректно обрабатываться;
не ломать бота.

Использовать:

Loguru.

17. Уведомления

Все Telegram-уведомления должны идти через:

NotificationService

Не отправлять сообщения напрямую из Scheduler.

18. Scheduler

APScheduler используется только для:

проверки дат;
создания задач;
запуска автоматических процессов.

Scheduler вызывает Service.

Не содержит бизнес-логику.
