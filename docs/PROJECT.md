# ProGaz Telegram Bot

## 1. Общая информация о проекте

Название проекта:

ProGaz Telegram Bot

Тип проекта:

Внутренняя корпоративная система на базе Telegram-бота.

Назначение:

Автоматизация учета объектов газовой компании, планирования выездов инженеров, контроля технических проверок и учета оплаты счетов.

Проект предназначен для внутренних сотрудников компании ProGaz.

---

# 2. Цель проекта

Создать Telegram-бота, который позволит компании:

- вести учет обслуживаемых объектов;
- автоматически планировать проверки объектов;
- уведомлять инженеров о предстоящих выездах;
- контролировать выполнение работ;
- создавать и отслеживать счета;
- контролировать оплату через бухгалтера;
- хранить историю обслуживания объектов.

---

# 3. Основная идея системы

Компания обслуживает множество объектов.

Каждый объект имеет:

- свой адрес;
- закрепленного инженера;
- индивидуальный день ежемесячной проверки;
- график обслуживания;
- необходимость периодического выставления счетов.

Telegram-бот автоматически контролирует эти процессы.

Пример:

Объект:

"Газовая котельная №15"

Дата проверки:

15 число каждого месяца

Инженер:

Иван Иванов

Система автоматически:

1. Рассчитывает дату следующего выезда.
2. Проверяет, является ли день рабочим.
3. Если дата попала на выходной — переносит на ближайший рабочий день.
4. Отправляет уведомление инженеру.
5. Отправляет уведомление администратору.

---

# 4. Пользовательские роли

В системе существует три типа пользователей.

---

## 4.1 Администратор

Главный пользователь системы.

Права:

- управление объектами;
- управление сотрудниками;
- назначение инженеров;
- изменение графиков;
- контроль счетов;
- просмотр истории;
- получение уведомлений.

---

## 4.2 Инженер

Сотрудник, выполняющий выезды.

Права:

- просмотр назначенных объектов;
- получение уведомлений;
- просмотр информации по объекту;
- подтверждение выполнения проверки;
- добавление комментариев.

---

## 4.3 Бухгалтер

Работает только со счетами.

Права:

- просмотр счетов;
- изменение статуса оплаты;
- отметка "оплачено".

---

# 5. Основной функционал

---

# 5.1 Управление объектами

Администратор может:

Создать объект.

Поля объекта:

- название;
- адрес;
- инженер;
- день ежемесячного выезда;
- необходимость полугодового обслуживания;
- стоимость обслуживания;
- комментарий.

---

Редактирование объекта:

Администратор может изменить:

- название;
- адрес;
- инженера;
- дату проверки;
- стоимость;
- комментарий.

---

Удаление объекта:

Удаление возможно только для администратора.

---

# 5.2 Планирование выездов

Каждый объект имеет индивидуальный график.

Пример:

Объект 1:

5 число

Объект 2:

10 число

Объект 3:

15 число

Объект 4:

20 число


У всех объектов разные даты.

---

# 5.3 Работа с выходными днями

Если дата проверки выпадает на:

- субботу;
- воскресенье;

система автоматически переносит проверку.

Пример:

15 августа 2026:

суббота

↓

перенос:

17 августа 2026

понедельник

---

# 5.4 Изменение даты проверки

Администратор может изменить дату.

Есть два варианта:

---

## Временное изменение

Только для текущего месяца.

Пример:

Было:

15.08.2026

Стало:

20.08.2026


Следующий месяц остается:

15 число.

---

## Постоянное изменение

Меняется весь график.

Пример:

Было:

15 число каждого месяца

Стало:

20 число каждого месяца.

---

Дата вводится вручную:

Формат:

ДД.ММ.ГГГГ

Пример:

20.08.2026

---

# 5.5 История проверок

Система должна хранить историю всех выездов.

Для каждой проверки хранится:

- объект;
- инженер;
- плановая дата;
- фактическая дата;
- статус;
- комментарий.

---

Статусы:

planned

Запланировано.


completed

Выполнено.


missed

Не выполнено.


cancelled

Отменено.

---

# 5.6 Уведомления

Система автоматически отправляет сообщения.

---

Инженеру:

Пример:

"Сегодня необходимо выполнить проверку объекта:

Название:
Газовая котельная №15

Адрес:
г. Москва...

Дата:
20.08.2026"

---

Администратору:

Пример:

"Сегодня запланирована проверка объекта:

Газовая котельная №15"

---

# 5.7 Полугодовое обслуживание

Некоторые объекты требуют расширенного обслуживания.

Раз в 6 месяцев система создает напоминание.

Пример:

"Необходимо выставить счет за полугодовое обслуживание объекта №15"

---

# 5.8 Работа со счетами

Каждый счет имеет:

- объект;
- сумму;
- дату создания;
- статус оплаты.

---

Статусы:

waiting

Ожидает оплаты.


paid

Оплачен.

---

# 5.9 Работа бухгалтера

Бухгалтер получает список счетов.

После оплаты:

Нажимает:

"Оплачено"


Система:

1. Меняет статус счета.
2. Записывает дату оплаты.
3. Отправляет уведомление администратору.

---

# 6. Пользовательский интерфейс Telegram

Интерфейс строится на:

- кнопках Telegram;
- меню;

Календарь Telegram НЕ используется.

Все даты вводятся текстом.
